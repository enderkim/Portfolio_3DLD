## 편집 범위

현재 사이트의 도트 배경, 유리 느낌 패널, 메인·작업·경험·소개 순서와 스크롤 동작을 유지합니다. 작품 클릭 후 열리는 상세 작업 양식을 아래 순서로 교체합니다. 이미지 약 70%, 텍스트 약 30%를 목표로 설명을 짧게 유지합니다.

Canva에서 확인한 톤은 어두운 장면, 큰 흰색 제목, 얇은 붉은 선입니다. 9페이지는 설계도와 POI/탑뷰, 10페이지는 공장 외부, 11페이지는 내부 공간, 12페이지는 같은 장면의 LightingOnly / Lit 비교입니다. **12페이지는 시간에 따른 수정 전후 자료로 확인된 것이 아닙니다.**

## 채워 넣을 예시 콘텐츠

### 1. HERO

**OUTBREAK**

UE5 · PC · 3인 스쿼드 · 익스트랙션 서바이벌 × 좀비 PvPvE

실제 작업을 대표하는 전장 스크린샷 1장을 크게 배치합니다. Canva의 콘셉트 이미지를 실제 UE5 작업 화면으로 표시하지 않습니다.

### 2. Goal + Role

**Goal** — 소음으로 달라지는 좀비의 이동과 밀집도 속에서, 스쿼드가 자원 확보와 탈출 경로를 판단하는 공간을 설계합니다.

**Role** — 게임 컨셉 및 방향 설계 · 전체 레벨디자인 및 그래픽 최적화 · UI 제작

주역량은 레벨디자인, 보조 역량은 환경 구성과 라이팅입니다. 다른 팀원이 담당한 좀비 AI나 익스트랙션 시스템 구현을 본인의 개발 성과로 표시하지 않습니다.

### 3. Process

| 단계 | 짧은 설명 | 사용할 자료 |
| --- | --- | --- |
| Reference | 가구·프랍을 리서치하고 로비와 전장의 공간 구성을 정리 | 실제 레퍼런스/설계도 |
| Blockout | 항공모함 로비와 전장 1·2의 공간 배치 설계 | 실제 블록아웃 자료 확보 필요 |
| Iteration | 내부 공간·프랍·라이팅 작업과 건물 간 이동 QA | 작업 버전과 비교 화면 |
| Final | 프랍 조정·정리, 최적화와 최종 폴리싱 | 최종 화면 및 확인 가능한 기록 |

기획서의 1~3차 발표 작업 항목을 정리한 것입니다. 실제 블록아웃 이미지, 테스트 결과, 완료 여부가 확인되지 않은 부분을 완료 성과로 단정하지 않습니다.

### 4. 핵심 Breakdown

- **Player Flow** — 항공모함 로비 → 오염 구역 진입 → 자원 회수 → 탈출. 전장 1·2의 역할과 POI를 탑뷰로 설명합니다.
- **Noise & Encounter** — 플레이어의 소음이 좀비 이동과 밀집도를 바꿉니다. 걷기·수집, 질주·근접, 총기, 폭발·사이렌에 따른 위협 변화를 공간과 연결해 보여줍니다.
- **Traversal & Environment** — 익스테리어·인테리어 연결, 건물 간 이동 QA, 프랍·라이팅과 그래픽 최적화를 짧게 정리합니다.

### 5. Before / After

같은 위치와 시점의 실제 초기·수정 화면 2장을 사용합니다. “문제 → 변경 → 확인 결과”를 한 문장으로 설명합니다. 실제 비교 자료와 QA 기록은 추가 확보가 필요합니다. LightingOnly / Lit는 보조 환경 아트 비교로 표시할 수 있지만, 블록아웃 또는 플레이테스트 수정 전후로 바꾸어 쓰지 않습니다.

### 6. Final Shots

최종 작업 이미지 3~5장: 전장 외부, 내부, 항공모함 로비 등. 장소·담당 범위만 짧게 표기합니다. 확보하지 않은 화면을 AI로 만들어 실제 작업물처럼 사용하지 않습니다.

## 이어서 할 일

1. Canva의 사용 가능한 실제 작업 이미지를 가져와 출처와 내용을 확인합니다.
2. `content.js`와 `app.js`에 OutBreak 예시와 공통 상세 양식을 구현합니다.
3. 실제 수정 전후/블록아웃 자료가 부족한 영역은 자료 구분을 명확히 합니다.
4. 데스크톱·모바일에서 이미지, 스크롤, 상세창 열기·닫기를 확인합니다.

현재 패키지를 GitHub에 올려도 위 개편이 자동으로 적용되지는 않습니다.
